# `/hora-setup`

*[English](./hora-setup.md)*

**このリポジトリが自分で書く唯一の skill です。** 仕様書が宣言したリポジトリを作り、案件の名前を持つ値を埋め、実際に届いたものを読みます。

`/hora` は `@openreachtech/hora` 由来の4つと同じように指揮し、直接実行もできます。手順そのものは [`SKILL.md`](../kit/skills/hora-setup/SKILL.md)、コマンド全体の中での位置は `hora-core` の [`commands.ja.md`](https://github.com/openreachtech/hora-core/blob/main/docs/commands.ja.md) にあります。このページが述べるのは、なぜこれがここにあるのか、そしてあなたに何を要求するのかです。

---

## なぜキットに入っていないのか

Hora Kit が配る他の skill は、すべて順序と関所についてのものです。これだけが、あるスタックの話を最初から最後まで扱います — どのリポジトリが要るか、何がそれを満たすか、届いた後に何を読むか。**スタックを知らないパッケージは、その答えを持てません。** だから、それを知っている boilerplate が skill を書き、装備します。

答えそのものも skill の中にはありません。[`docs/stack/`](./stack/README.ja.md) にあり、skill が実行時に読みます。スタックが変わればそのディレクトリが変わり、skill は編集不要です。

---

## 何をするか

```
1. 宣言に従い、足りないリポジトリだけを作る
2. この案件の名前を持つ値を埋める
3. 取得したものを実地で読み、.hora/tree/ に記録する
4. 作った行に対し、テストキャッシュを配線する（それを覆う skill があるときだけ）
```

**手順3は何も焼き込みません。** 常に最新のリリース済み状態を取得するので、ここに書き下した規約はいずれ実物と食い違います。読んだ内容は、読んだ時点のタグとともに `.hora/tree/<repository>.md` に控えられ、そのタグが変わったときに読み直されます。

**手順4が引き渡すのは一覧だけです。** 作った行ごとに1つの検証単位、それぞれのテストコマンドが既に記録された状態で渡します。キャッシュ宣言がどういう形かは、キャッシュを覆う装備済み skill のものです。配線したか、覆う skill が無くて飛ばしたかは、`.hora/tree/<repository>.md` が行ごとに述べます。

---

## 何を読み、何を書くか

| | |
|---|---|
| **読む** | `specs/<version>/spec.md` のリポジトリ構成と案件名、`docs/stack/` のスタック・ハンドブック、各リポジトリの実物のツリー |
| **書く** | 実装リポジトリ、このリポジトリ自身の `package.json`・`.gitignore`・`eslint.config.js`、`.hora/tree/` |

**`specs/` に対しては読み取り専用です。** そこへ書くのは `/hora-spec` と `/hora-plan` だけで、どちらも書く前に一字残らず提示します。

---

## どこで止まって尋ねるか

いずれも調べれば分かる事実ではなく決定事項なので、推測せずに止まります。

| | |
|---|---|
| 入口にリポジトリ構成セクションが無い | リポジトリを増やすのはアーキテクチャの決定 |
| 案件名が無い | ディレクトリ名から導出してはならない |
| スタックのカタログに無い `Origin` | その値は origin ではない |
| origin が定めた範囲外の行数 | その範囲はスタック自身の制約 |
| サーバーの表が無い | それが無いと契約を導出できない |
| 宣言された `Directory` が存在しない | 放置すればその名前の上に何かを作ってしまう |

**スタック・ハンドブックが無い場合も止まります。** 宣言が無い場合と同じで、推測は決してしません。

---

## 各行のディレクトリと、2つの除外リスト

行の着地先は `<案件名>-<宣言された行>` です。構成表の任意列 `Directory` に別の指定があればそちらに従います。

| `Directory` | 挙動 |
|---|---|
| **省略** | `<案件名>-<宣言された行>`。無ければ取得する。既定であり、新規プロジェクトが出会うのはこちら |
| **記述あり** | そのディレクトリだけを見て、**決して取得しない**。書いてあること自体が「既に存在する」の宣言 |

**そのうえで、そのディレクトリを `.gitignore` と `eslint.config.js` に登録し、登録したことを報告します。** 組み込みのパターンが覆うのは既定の名前です。それ以外の名前を付けたディレクトリはどちらにも一致せず、しかも両方の失敗が沈黙します — 除外されなかったリポジトリはこのリポジトリへ丸ごとコミットされ、ルートの lint は自分の設定ではないリポジトリへ踏み込みます。

**その報告が出たか確認してください。** 実行の中で、抜けたときの損害が大きく、しかも静かなのはここだけです。

---

## しないこと

boilerplate の取り込み（vendoring）、上流リモートの保持、サブモジュール化、`npm update`、ミドルウェアの起動、そしてあなたが既に埋めた値の上書き。

**既に存在したリポジトリは、自分の履歴を保ちます。** `.git` を捨てて再初期化するのは、この実行が取得した boilerplate に対してだけです。他人のコミット数百件があなたの `main` に着地しないためです。あなたが自分で置いた行はそれを丸ごと飛ばします — キットはリポジトリの上に被せるのであって、上書きするのではありません。

---

## 版ごとに再実行される

リポジトリは後から増えます。スマホアプリ向けの API として始まった案件が、管理画面を持つようになる、といったことです。**一度通れば終わりではありません。** 既にあるものは通過するので、再実行は安全です。

**記録と実物が食い違ったときは、常に実物が勝ちます。** `.hora/tree/<repository>.md` はそこから書き直されます。
