# スタック・ハンドブック

*[English](./README.md)*

**このディレクトリが、hora スキル群を技術スタック非依存にしているものです。** `.claude/skills/` にインストールされるスキル群が持つのは順序と関所だけで、この boilerplate の技術スタックに固有のこと — どのリポジトリを取ってくるか、何を埋めるか、どんなミドルウェアがあるか、API 操作が何を生み出すか — はすべてここにあり、スキルは実行時にこれを読みます。

これは kit が `@openreachtech/hora-skills-ort-*` パッケージに対して既に適用している分担と同じ形です。hora スキルは「必要な情報の種類」を述べるだけで、答えを焼き込むことはありません。規約と合否基準の答えは装備されたスキルから description のマッチで得ます。スタックの構造の答えはこのディレクトリから、決められた場所で得ます。

**場所そのものが契約です。** hora スキルはプロジェクトルートの `docs/stack/README.md` を探します。これが無い、あるいは必要な項目が欠けているとき、スキルは止まって質問します — スタックを推測することはありません。

## origin カタログ

**spec のリポジトリ構成セクションが `Origin` 列に書いてよい値は、この表の行がすべてです。** この表に無い行は origin ではなく、`/hora-setup` はそこで停止します。

| Origin | Boilerplate | 役割 | 個数 |
|---|---|---|---|
| `renchan` | `openreachtech/renchan-boilerplate` | backend — API とジョブ。DB を持つ | **必ず 1 つ。** 1 つの DB システム = 1 リポジトリ |
| `furo` | `openreachtech/furo-boilerplate-nuxt` | Nuxt frontend — 画面のひとまとまり | **0 個以上。** 1 リポジトリに Nuxt アプリは 1 つなので、画面のグループごとにリポジトリが分かれる |

- **backend が 0 個、あるいは 2 個以上なら stop-and-ask** — 2 つめの DB システムの宣言は行を足す話ではなく、アーキテクチャ上の決定
- **frontend が 0 個は正常。** スマホアプリ向けの API だけのプロジェクトもある
- **1 つの `renchan` リポジトリは複数のサーバーを並べて持つ** — 従業員向け GraphQL サーバー、管理者向け GraphQL サーバー、REST API、Worker — が 1 リポジトリの別フォルダに同居する。DB を共有するサーバーは 1 つのリポジトリに属する

## 各 origin 文書が答えること

origin ごとに 1 ファイル、[`origins/`](./origins/) 配下。それぞれが次をこの順で確定します。

| セクション | 確定すること |
|---|---|
| **どこから来るか** | リポジトリ URL と、取得するバージョンの選び方 |
| **何を埋めるか** | boilerplate が持ってくるすべてのプレースホルダー — パッケージの値、環境変数の値 — と、それぞれに入れる値 |
| **何を置くか** | boilerplate は同梱していないがプロジェクトに必要なファイルと、その置き場所 |
| **その行へコピーするスキル** | 作られたリポジトリ自身の `.claude/skills/` へコピーする装備スキル。そこで直接作業するセッションから届くようにするため |
| **届いたら何を読むか** | `/hora-setup` が実物の木を読むときのチェックリスト。読んだ結果は `.hora/tree/` に記録される |

## ハンドブックの残り

| ファイル | 内容 |
|---|---|
| [`origins/renchan.md`](./origins/renchan.md) | backend リポジトリの取得と初期化 |
| [`origins/furo.md`](./origins/furo.md) | frontend リポジトリの取得と初期化 |

| [`artifacts.md`](./artifacts.md) | API 操作の種別ごとに、各実装レイヤーで何が生み出されるか |

## このハンドブックでないもの

- **boilerplate の規約のコピーではない。** resolver をどう書くか、テーブルをどう形作るか、レビューが何で落とすか — それらは `@openreachtech/hora-skills-ort-*` パッケージと boilerplate 自身の木のもの。このハンドブックが持つのは、この boilerplate 群を*選んだ*ことから従うものだけ: 何が存在し、どこから来て、何を埋めなければならないか
- **実物の木の代わりに読むものではない。** `/hora-setup` は実際にクローンされたものを読み、実物はここに書かれたどんなことよりも優先される
- **kit のものではない。** hora スキルはこの内容を決して書き写さない。この boilerplate のスタックが変わるときはこのディレクトリが一緒に変わり、どのスキルにも編集は要らない
